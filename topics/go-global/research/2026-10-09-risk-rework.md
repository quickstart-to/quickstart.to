# 风控与账户安全精修：确认访问失效，也确认业务恢复

日期：2026-10-09。起点为 `5b6d97f` 的 `chapters/11-risk.md`。对照同版快速入门及 editorial-baseline，不视为读者已验收。

## 退稿诊断与承诺

现稿从“扩大收款规模”开始，安全工作的范围被交易框住。账户、争议、出款与数据事件仅列步骤，末尾要求读者演练却没有本章实际执行的产物；“钱没到”大幅重复提现章。需要帮助一人维护产品的开发者在异常出现时确定优先级、保留最小证据、恢复控制与用户任务，避免把换密码或改平台当成所有问题的答案。

新增能力：识别能控制其他系统的账户与恢复依赖；遇到疑似凭据泄露时分别证明旧访问失效、正常业务恢复；把用户求助、正式争议、资金限制及数据通知交给适当流程。提供完成的事件记录与隔离演练，不能将合成交易或假设事故写成真实生产事故。

## 决定性问题与调研计划

- 恢复依赖怎样形成单点，如何验证备用路径：责任方恢复/多因素/凭据撤销文档与原作者事故复盘；不能操作真实账号来试验。
- 删除泄露文件、撤销凭据、轮换部署、停止滥用分别证明什么：官方密钥文档与已公开事故；在仅监听本机的合成服务里实际演练旧凭据仍有效、撤销后失效及遗漏任务尚未恢复。
- 第一份用户求助/正式争议要提供哪些事实：MoR 责任边界、当前争议提交要求与完整的合成案件记录；保留无云端报告正文的证据限制。
- 数据事件何时进入通知评估：PIPL、GDPR 具体条文与当前中国网络安全事件报告规则，避免一律套 72 小时。

中英文搜索原始密钥泄露、账号锁定和恢复复盘；优先真实过程与反例，不采用“绝不封号”“秒解冻”等营销说法。与基础设施章区分：不重做旧备份练习，本章验证访问控制与轮换后业务的两道结果。

## 实际执行与示例边界

`assets/credential-rotation-drill.mjs` 仅内置合成密钥、本机 HTTP 与自己创建的临时文件；不读取真实环境密钥、不连接第三方。实际首跑环境 macOS / Node.js v22.19.0，时间与 10 次请求结果见 `2026-10-09-credential-rotation-result.json`。删暴露副本后旧密钥仍返回 200；新网站配置不影响旧访问；签发方撤销后旧密钥与漏更新任务返回 401，网站仍 200；补齐任务后 200，旧密钥仍 401。状态与响应 code 同时断言。

网页演示只复现因果状态，不冒充 HTTP 实测；实际执行另由下载脚本提供。服务端真实账号、会话、其他凭据与持续入侵不在演练范围。SUPPORT-DEMO-04 是完整合成客服时间线，20 美元/30 天/无自动续费及 CSV 留在浏览器的前提与相邻章一致。它确认示例权益恢复，不虚构已完成用户报告导出；事件摘要也明确调查仍未完成。

## 独立退稿检查及修复

对比 `5b6d97f` 和快速入门的新增能力：旧稿只列账号/交易操作与建议演练，现稿让读者分别识别恢复依赖、关闭旧访问、发现遗漏的任务，并从准确证据决定怎样回复客户。相对基础设施章新增的是访问失效与业务恢复这两道验证，没有再做备份教程。

首次完整读取渲染正文后记录的具体退稿点：

1. 流程图末尾才出现“评估通知”，可能把有时限工作放到业务恢复之后。修复为发现阶段同步判断，汇合后按新进展补充；正文亦禁止等待全部调查结束才计时。
2. 实测后举例“后台发送报告就绪通知”，与本例报告在浏览器处理的前提冲突。改为后台发送购买确认邮件。
3. 数据报告表没有明确中国时限的发现/获知起点，GDPR 个人通知未提法定例外。按第四条和第三十四条补齐，同时不把“普通运营者”替代法条的“其他网络运营者”。
4. 客服记录只有行为没有可核对顺序。补全合成订单与同日 UTC 的 10:00 付款、10:01 权益失败、10:12 求助、10:18 修复、10:26 确认可进入，保留未证明导出的限制。
5. 删去“为什么重投”的自问自答和“不要复制支付实现”的内部编辑用语，直接连接平台事件契约与证据保留。

修复后再读相关段落与两图、客服记录、法律表，未发现与本章承诺相冲突的核心缺口。图、交互和实测分别讲恢复依赖、两个验证结果、真实本地请求，不用图库填充。仍不把编辑自审当作维护者接受，也不声称生产安全已经验收。
