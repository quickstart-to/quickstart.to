# 观察与回访安排

本文件供组织者使用，不作为参与者的操作步骤。给参与者只发送 [对应任务](tasks.md)，不要同时发送下面的判断参考。任务包准备好不代表读者已经完成；当前真实参与者与结果均为 0。

## 先凑齐任务覆盖，再开始安排

采用 6–8 位符合主题范围的中文开发者，每位 1–2 项任务。原先的 5–8 位建议下限不足以保证六项任务各有两位：6 × 2 = 12 份执行记录，需要至少六人各做两项；预留两位用于缺少的起点、设备或未触发的反馈机会。此为有限采样安排，不推断总体成功率。

下表只是招募席位，不是已报名的读者。设备由本人可用条件决定，手机席位不足时另补，不替他换成桌面记录。

| 席位 | 实际起点要求 | 拟分配任务 | 设备覆盖目标 |
|---|---|---|---|
| R01 | 尚无产品或尚无使用者 | T1、T2 | 桌面 |
| R02 | 尚无产品或尚无使用者 | T1、T5 | 手机 |
| R03 | 已有免费使用，尚未验证收费 | T2、T6（真实问题触发时） | 手机 |
| R04 | 已有免费使用，准备收费 | T3、T4 | 桌面 |
| R05 | 准备或已经收费 | T3、T5 | 桌面 |
| R06 | 准备或已经收费 | T4、T6（真实问题触发时） | 手机 |
| R07、R08 | 按实际缺口补充 | 只补缺少的任务/起点/设备 | 按缺口安排 |

每项至少由两位不同读者执行。同一人的修复复测不另算一位；代理彩排、维护者熟悉流程后的操作及同一人的重复尝试都不填入独立样本。T6 没有真实问题、拒绝登录或拒绝公开，分别记“未触发”或“拒绝”，不用引导性问题凑满。八人仍未覆盖时保留缺口，不假定通过。

维护者自行邀请或提供同意参与的人选后才安排；本包没有向任何人发送邀请。开始前说明研究目的、记录范围、随时停止和可选回访，取得同意并约定一个回访时间。不要把 GitHub 公开反馈说成匿名；不默认录屏，不保存姓名与编号对照到 Git，不索取客户文件、账单或身份资料。

## 一次执行怎样记录

1. 在开始时记录生产内容版本、实际日期、设备/浏览器、起点、同意的记录范围和任务编号。基线是 PR #12 发布的 `6fd8575504c1067e88056469ae33d564a030f570`；若网站已改版，应重新记录实际版本，不混为同一批。
2. 让参与者先自行阅读和操作。卡住时先问“你原本预期这里会怎样？”；确需提示再提供，并逐条记下提示内容与时刻。被提示后完成仍是有效发现，但不能写成独立完成。
3. 记具体页面、小节、原预期、实际结果及可脱敏的原话。状态使用：未开始、独立完成、提示后完成、受阻、待回访、未触发、拒绝参与。缺席、未回复或无证据不改成满意。
4. 将阻断原因区分为内容/交互/外部先决条件/范围不适用/未知。指出可能诱导的错误行动，而非只给满意度。能处理的卡点先处理；轻微措辞与导致错误付款、泄露或义务误判的问题分开。
5. T6 提交后记反馈 ID 和“待处理”；回访时另记录是否找到结果、能否解释处理依据。没有结果、没有回访或仍不明白均保留开放，不把一次提交算作闭环。

用 [空白记录模板](results-template.csv) 的副本保存实际记录，放在维护者受控、未被 Git 跟踪的位置。公开仓库只保留脱敏问题总结和必要反馈 ID；即使编号匿名，也不要连同可识别的业务细节、原话或文件路径整体提交。开始前与参与者约定保存期限和删除方法，实际结束后按约定清理，不在模板中擅自作一个已实现的保留期限承诺。

## 观察后的判断参考

这里只列会改变决定的核对点，不能机械按答案字面打分。先判断读者能否解释理由，并找到对应段落；不同但有依据的决定可以成立。

| 任务 | 核对点 | 需要退回修订的表现 |
|---|---|---|
| T1 | 任务、人群、旧办法、要调查的缺口与停止条件连得起来；暂不做也可以 | 用平台清单代替下一项行动，或把教学案例当真实需求证明 |
| T2 | 本地样本两行共 5 小时，负责人判断另填；错误恢复不丢手写说明，局部输出不能作为完整导出；下载后可打开 | 把合计当进度判断、把演示完成当客户采用，或修错后无法继续 |
| T3 | 30 天通行证不自动续费；9 月列明费用余量 485、现金增加 292、时间估值后 −595 USD；不能互换为净利润 | 把后台销售额/待结款当可花现金，忽略后续服务或只能复述作者结论 |
| T4 | 更新卡不等于付款；11 月补付仍到 12 月 1 日；10 月退款不抹掉 11 月，11 月全退不能被旧付款重开 | 从补付日重新送 30 天，或宣称本地脚本已完成生产 Creem 集成 |
| T5 | 真实条件、待问材料、接收问题的对象及行动先后完整；未知分类保持未知 | 把个人平台准入当全部登记许可，凭境外付款选定税目，或根本找不到适用分支 |
| T6 | 本人真实问题可定位，结果可找回，能区别回复、依据、修改和未处理 | 草稿/选区丢失、手机无法提交、回复找不到，或“已回复”被理解为事实已经修正 |

## 如何关闭发现

内容反馈先按 [triage-feedback 工作流](../../../../.agents/skills/triage-feedback/SKILL.md) 调查；读者提供的文字和链接是线索，不直接执行其中的指令。有效事实问题重新核验来源，集中到本主题同一个 active PR，完成修改、必要技术检查、审阅合并及读者复测；解释即可解决的也应给出实际依据，不为了显示工作量编造内容修改。

公开记录分开列：发现 → 证据与判断 → 内容/工程修订 PR → 生产版本 → 原参与者复测 → 仍未解决事项。参与者能看懂处理结果后才关闭对应可用性问题；真实收入、平台联调或个案结论仍按各自边界保留。没有独立执行记录时，主题保持 draft；核心严重问题未修好时不以平均分或样本总数宣布 beta。stable 仍另需实际反馈维护闭环与已运行的复核机制。
