# 应用商店章精修：从手机任务到可维护的发布

日期：2026-10-09。起点为 `6929f4b` 的 `chapters/10-app-stores.md`；参照同版快速入门及 `editorial-baseline.md`，不把参照稿视为已获读者验收。

## 退稿诊断与写作承诺

现稿“先决定是否需要商店分发”没有完成一项取舍，后半部集中注册、支付与出款；读者无法据此安排可测试版本、准备审核材料，或判断更新后故障该如何处理。四个里程碑又把真实购买写得像所有应用都必须经历的上架阶段。现稿缺原始开发者案例、相互连接的发布图及完成的发布记录。

本章帮助已有产品想法的大陆个人开发者决定是否投入手机端，并把一个有明确移动任务的候选变为测试、审核、发布与维护计划。新增能力是控制分发及版本风险，不重复快速入门的需求访谈或提现章的到账对账。周报 Web 案例可得出暂不做 App；如换成手机现场采集任务，应明确是另一个教学候选，不能虚构现有用户需求。

最可能推翻原生推荐的假设：手机网页或现有工具已能以可接受成本完成同一任务。必须同等检查 Web 的能力与局限，不能把离线、相机、安装等一概说成原生专属。

## 决定性问题与查询计划

| 决定 | 所需证据或演示 |
|---|---|
| 何时做 App，何时留在 Web | 中文、英文原作者开发复盘；Web/原生替代与维护代价；完整教学选择 |
| 用什么身份、先做哪个平台及地区 | Apple/Google 当前注册、身份展示及测试规则；不把国籍推成服务地区 |
| 测试怎样转成可提交版本 | 官方测试/审核材料要求、原始拒审经历；完成的任务/缺陷/修复记录，标明未实际执行 |
| 数字权益怎样处理 | 当前支付规则与地区例外；恢复、退款、账号退出边界；不套用 Web MoR 按钮 |
| 上线后怎样发现并限制故障 | 官方分阶段发布/暂停边界；版本与用户影响演示，暂停不能撤回已安装版本 |
| 不做了怎么办 | 已有用户/购买/数据/账户的交接逻辑；政策结论需官方依据 |

## 研究覆盖与采用边界

已重读现稿 8 条引用：Apple 入会、收款、支付指南；Google 入会（展开费用、身份、设备各项）、新个人账号测试、支付政策、支持地区；工信部备案通知。政策均在 2026-10-09 重新查看，不使用旧经验文中的支付禁令或处理时间。当前引用日期原本已为同日，未虚增日期。

新增 11 条来源及短摘录，来源总表为 148 条：

- `src-shudao-sticki-porting` 与 `src-shudao-sticki-launch`：2026-06-07/14 同一中文开发者连续周记，完整读 Sticki 开发与发布段。原文显示移植的引擎/设备/配置成本，上架后发文时零下载。采用这些历史经历，不把提工单和获批的时间相邻写成因果，不把零下载外推为平台普遍无流量。作者经营该产品，未独立验证其结果。
- `src-panic-transmit-ios-retirement`：2018-01-05 团队原文，完整读正文至 Thank You。产品有重度使用者但收入不足覆盖开发，停售时安排最后更新、保持同步和用户支持。采用持续维护与退出逻辑；团队与大陆个人情境不同，不采用当时收入、再下载/退款政策及文中系统版本说法。评论只作背景，不作现行规则。
- `src-apple-app-review`：实际读 2.1/2.2/2.3、4.2、5.1.1 等相关条款，覆盖完整构建、测试渠道、功能价值、访问、隐私、账号删除。支付部分仍独立引用同页既有条目，已重新读 3.1.1/3.1.1(a)/3.1.3(f)。没有把美国店面例外扩成全球外链许可。
- `src-apple-testflight`：测试信息、外测首构建审核、反馈和另行正式审核；不把普通测试者变成团队后台成员。
- `src-apple-phased-release` 与 `src-google-play-staged-rollout`：全文及 Google 暂停/增加比例展开项。均是版本更新；Apple 自动更新比例不限制所有手动下载，累计暂停 30 天；Google 暂停保留已有新版。这些差异决定演示只采用 Google 的更新暂停背景。
- `src-apple-review-replies`：回复及材料附件、纯元数据问题可沿用构建，不能为代码缺陷只改说辞。
- `src-google-play-review-preparation`：App content 相关声明、访问、权限、年龄与评级；只采用已读部分，不做特定敏感应用许可判断。
- `src-apple-app-privacy-details`：开篇及申报/收集定义、可选披露和数据类型前半，采用第三方数据实践也需核查的范围，不声称已核某个真实应用的数据标签。

未采用：搜索中大量代上架、自动生成与工具推广文章；`https://kanchuan.com/blog/11` 虽是原创审核经历，但包含旧支付禁令、电话和固定时差等不宜沿用内容，本次只作为研究对照、不入来源。没有从这些文章提取过审捷径。没有用厂商“原生更好”叙事替代手机 Web 与现有模板的同任务比较。

- `src-google-play-account-information`：复审发现个人信息展示比较不对称后新增核查。读取个人/组织资料和联系信息区分：个人开发者展示名称可不同，法定姓名、国家和开发者邮箱仍公开；变现公开完整地址，特定地区还有附加要求。补回正文表格，不能只提醒 Apple 的姓名公开。

## 独立退稿复读与修复

以浏览器中完整正文重新阅读并对照快速入门基线，发现并修复以下具体问题：

1. 身份比较仍让 Google 一栏停在“自己核对”，Apple 却给了姓名展示规则。新增官方账号资料页核查，补齐法定姓名、国家、邮箱和变现地址的展示范围；开发者别名不等于匿名。
2. 第一版图把“已有工具够用”与原生发布连在同一条直线，可能误导读者仍需往下做 App。改为停止支路与原生支路；测试、审核和运行失败分别有返回修复的连接，不再仅靠并列卡片暗示流程。
3. 末尾完整计划与前面的解释重复。删去重复总结段，把里程碑改为本例已经选定的安排及仍需得到的结果；避免把购买写成所有应用上架的必要步骤。
4. 两处 Markdown 强调标记在中文句号与下一句之间没有正确解析，浏览器中出现原始星号。将句号移出强调范围，重载核实；测试记录同时用明确假设标记，未把构建 13 方案写成已修复。
5. 继续保留具体边界：选 iOS 源于合成设备和支持条件，未证明真实需求；新的照片报告不是周报工具的已上线移动版；暂停后的修复按钮表示已完成安装，不是发布后自动生效。

相对快速入门，新增的是是否投入客户端、把可复现失败转为构建决定与审核说明、区分发布暂停和设备修复的能力。Shudao 的移植/上架经历说明发行不替代适配或获客；Panic 的退出安排说明维护责任延续到停售之后。两者不是成功率证据。没有新增视频：现有材料中未找到比原文和版本演示更能解释本章决定的已核媒体，不为数量重复嵌入入门讲座。
