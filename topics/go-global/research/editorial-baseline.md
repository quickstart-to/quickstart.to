# 从快速入门沉淀的写作基线

维护日期：2026-10-09。参照`quickstart.md`在ff663a8的版本；这是维护者认为相对更好的阅读基线，不是全专题已验收或最终精品的声明。后续反馈应修订本记录，不把一篇样稿固定成永久模板。

## 值得保留的做法

| 第一篇的具体位置 | 为什么有效 | 后续章节怎样继承 |
|---|---|---|
| 开篇从“部署、英文、支付都做好以后，用户为何需要它”进入，接中文开发者失败复盘 | 先呈现读者熟悉的困境，立即接到出海主线 | 选择本章自己的矛盾；不用通用励志开场，不再每章重复同一轮验证 |
| Plausible两次流量及定位、产品、内容一起改变 | 行动和条件解释结果，避免把成功归结为一条秘诀 | 展开少量案例的旧判断、新观察、调整与代价；不能只换人名加一句建议 |
| Tally传播与表单被人使用的关系，同时交代支持工作 | 说明方法为什么适合这种产品，保留迁移到别的产品时的限制 | 推荐要有适用条件与改变选择的条件，不能套用统一渠道清单 |
| 周报的工时事实与项目判断分别输入，读者能调整并看到结果 | 读者亲手发现自动化边界，而不仅是读一段结论 | 交互应有有意义的输入和可解释的变化；折叠文字只算阅读辅助 |
| 倾听与迁移插画、输入汇合图、回访判断图分别承担不同任务 | 建立场景、解释关系、定位下一步，减少长段落连续堆积 | 先问读者哪里需要看、比较或操作，再选媒介；不机械复制图数或布局 |
| 原讲座有中文导读、点击加载和原站入口 | 视频是补充路径，不看也能读懂，未播放内容不冒称已看完 | 原作者媒体需核查，新增视频要提供新的价值；不为凑媒体重复嵌入 |
| 来源、核验、AI维护统一在文末，案例首次说明 | 保留诚信而不反复打断阅读 | 普通插画说明集中，重要假设和数据状态就近标注一次；保留会影响决定的限制 |

## 第一次专章修订为何被退回

d99aa09的选品章有正确来源和可读图示，但没有充分展开选品：候选从何而来、现有方案是否已解决、为何淘汰或优先调查，仍缺少可复查的推导。大量内容重复快速入门的访谈与回访；“完整试验前决定”给出了结果，却缺输入比较。视觉主要是文字卡片，三个details并未让读者动手发现新关系。验收记录偏向罗列新增内容和技术通过，未有效执行退稿判断。

第二篇新增价值应是“从几个候选到一项可解释的投入决定”，而不是再次走完整个出海入门。应能从正文指出：哪些公开材料支持哪些事实，哪些仍是假设；谁被排除、为什么；哪种新观察会改变选择；读者做完得到什么。

## 不应固化的部分

- 周报工具只是贯穿教学案例，不能先认定其需求，再用研究为它找理由；必要时推导出暂停开发或更换任务。
- 第一篇也缺真实访谈与长期运行证据，不能借其相对完成度升级专题状态。
- 图片、来源数量、字数、视频和互动数量都不是质量指标；图文密度与节奏需逐篇判断。
- 通读后的自评不能替代维护者或真实读者反馈。报告“完成修订并待阅读反馈”比宣称机器味已消除更准确。

执行步骤统一见`docs/editorial-workflow.md`；本记录只保留这组文章的具体经验，避免再复制一套通用规则。
