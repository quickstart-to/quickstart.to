先卖一个范围明确、自己能持续交付的方案，再根据真实使用调整价格。把客户要付多少钱、能获得什么、何时再次扣款、如何退出放在同一张报价里；不要让代码里的默认值替你决定商业承诺。

本章的定价计算是工作方法，金额为虚构示例。平台行为以截至2026-10-09核验的Creem文档说明，其他支付平台要按各自文档重新验收。

## 先确定收费单位，再决定价格

从[选品与验证](/go-global/validate-idea)得到的工作场景出发，确定客户购买的结果，以及你为交付结果承担的成本。

| 收费单位 | 适合先验证的问题 | 必须写清的边界 |
|---|---|---|
| 一次成果或下载 | 客户是否只需要完成一次任务 | 格式、有效期、更新和支持范围 |
| 每个使用周期 | 是否有持续、重复的使用价值 | 周期、包含用量、续费、取消生效时间 |
| 按实际用量 | 客户能否理解并预测账单 | 计量单位、失败任务是否收费、预算上限 |
| 按席位或团队 | 购买者是否为多人协作付费 | 活跃席位定义、增减席位、权限和账单归属 |

不要同时引入多个难以解释的计费维度。对耗用API、存储或人工支持的产品，先明确用量边界；若想卖永久使用权，先写出服务依赖关闭后仍能交付什么，以及未来维护由谁承担。

## 用一张成本表排除无法兑现的报价

把订单金额、平台结算和自己能用于运营的钱分别计算。交易费、出款费、汇兑费的真实口径见[收款方案全景](/go-global/payments)和[提现与结汇](/go-global/payouts)。

下面所有数字都只是演算假设，不代表任何平台报价或税额：假设每月向一个客户收20美元，本期交易成本1.5美元、资源成本4美元、分摊支持成本3美元，先得到11.5美元的运营贡献。如果资源消耗变为12美元，这个数就剩3.5美元。

这还没有减去固定费用、退款损失、出款换汇费用及适用税负，不能称为净利润。分别算正常使用、重度使用、退款和收入中断时能支撑多久，再决定价格和用量限制。

建议先发布一档清晰方案。记录每个付费客户使用了什么、哪里需要支持、为什么退出；价格调整依据实际交付和购买行为，而不是只看同行价格表。

## 让报价、结账页和产品内权益保持一致

上线前逐项填写：

1. **金额与币种：** 是单次总价还是每期价格；税费最终如何展示，以实际结账页为准。
2. **交付内容：** 功能、用量、限制、支持范围，以及达到上限后的处理。
3. **扣款安排：** 首次扣款、续费周期、试用结束后的金额；试用是否需要支付卡。
4. **退出安排：** 取消入口、生效时间、剩余权益、退款申请方式。
5. **变更安排：** 升降级何时生效，是否补差价，旧客户是否受影响。

把这份记录与产品配置、邮件和后台页面对照。测试模式只证明流程可运行；上线前还要核对生产配置和真实客户看见的条款。

## 试用是一种具体的扣款安排

截至2026-10-09，Creem免费试用会验证并保存支付卡，试用结束后自动按常规价格扣款；试用期间取消则不收取该次试用后的订阅费用。付费试用会先收试用费，取消试用不自动退还这笔钱。修改产品试用设置只影响之后创建的订阅。[^src-creem-trials]

因此，不能只写“免费开始”，却把自动续费藏在下一屏。建议在开始试用前同时展示试用范围、结束时间、届时金额和取消入口；如果做的是无需绑卡的产品演示，就明确它与支付平台的自动续费试用不同。

也不要把`trialing`计为已付费。Creem把试用、有效、未付款和期末取消列为不同状态，并建议在生产中用webhook同步续费、失败及取消等变化。为试用开放的权益，应与已收妥款项的记录分别保存。[^src-creem-subscriptions][^src-creem-trials]

## 取消、退款和权益关闭分别核对

Creem支持立即取消和期末取消；期末取消时，客户在当前计费期结束前仍保有访问权。平台还提供客户门户取消和全额、部分退款操作。不要把“用户点了取消”直接实现为“立即删除账户”。[^src-creem-refunds-cancellations]

| 操作 | 产品需要确认的结果 |
|---|---|
| 取消未来续费 | 下一期不再扣款；本期权益按取消方式处理 |
| 退还某笔订单 | 退款金额、订单状态和客户通知；另查订阅是否仍会续费 |
| 降级或升级 | 新旧权益、生效时间和差额账单一致 |
| 删除账号 | 先处理订阅和导出请求，再按留存规则处理数据 |

这些是产品验收项，不是说所有平台会自动完成它们。特别是退款完成后，应再确认订阅状态和下一次扣款安排。消费者的法定撤回权与自主制定的退款政策还需分别判断，不能用“数字产品概不退款”概括，见[合规底线](/go-global/compliance)。[^src-eu-withdrawal]

## 改价格时，先区分新客户与旧订阅

截至核验日，Creem修改产品价格只作用于新结账；既有订阅继续按原价计费。迁移旧订阅需要明确操作，平台不会自动替你通知客户。升级、降级的方案变化立即生效，差额处理由相应行为参数控制，不能把“变更方案”“扣差额”“下期金额”当成同一件事。[^src-creem-subscription-changes]

建议先列出受影响的订阅、原承诺、拟生效日、客户通知和回退办法。在测试环境验证账单后，再按合同和适用规则处理真实客户。不要直接复制批量迁移脚本去修改所有旧订阅。

## 上线前跑完这张状态表

每个场景同时检查支付平台、自己的订单记录、用户权益和用户通知：

| 场景 | 要观察的结果 |
|---|---|
| 首次付款成功，页面中途关闭 | 以服务端确认的支付事件完成交付，重新登录仍可使用 |
| 试用开始、取消和到期 | 不把试用记为实收；取消入口有效，到期行为与承诺一致 |
| 续费失败后恢复 | 账单和权益按预先定义的宽限策略恢复，不重复记账 |
| 期末取消 | 本期继续可用，到期后按约定结束 |
| 全额或部分退款 | 实际退款额准确，另核对续费与权益 |
| 升降级和改价 | 本期差额、下一期金额、旧客户范围与通知一致 |
| 重复或延迟的事件 | 同一交易不重复交付；延迟事件不把新状态改回旧状态 |

具体webhook验签与服务端交付沿用[快速入门](/go-global)的接入步骤；遇到争议或异常扣款，转到[风控与账户安全](/go-global/risk)。
