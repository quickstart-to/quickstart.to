# 本主题的写作说明（给 Agent）

继承仓库根目录 `AGENTS.md` 与 `docs/content-guide.md`，以下为本主题补充。

## 读者与口吻

- 读者：中国大陆个人开发者，技术能力强，但对支付、外汇、税务、海外合规不熟。
- 口吻：有经验的同行在分享，直接、具体、给结论。不说教，不堆砌“注意事项”。
- 技术细节点到为止（读者会写代码）；把篇幅留给支付、合规、钱怎么回国这类读者最缺的知识。

## 编辑目标与贯穿案例

- 目标是有判断、有过程、有结果的出海实践指南。让读者知道当前条件下先做什么、为什么、做到什么程度算完成，以及遇到障碍怎样继续。按 `docs/content-guide.md` 的编辑验收标准审查，不能以章节齐全替代质量。
- 贯穿示例沿用“把表格生成客户周报的Web工具”：中国大陆个人、无海外公司起步，面向使用英语的小团队。它是明确标注的虚构推演，不赋予真实用户、收入、审核通过或到账经历；仅在有记录的操作上使用“实测”。
- 同一案例贯穿需求样本、报价、结账、交付、取消、回款及数据处理。所用价格与成本假设集中交代、跨章一致；平台费用另引当前来源。面向消费者、加入AI处理或进入新地区时，明确哪些假设改变，再展开相应分支。
- 快速入门选定有证据支持的适用场景与主路线；支付章负责完整比较，提现章负责资金与对账，主体/税务章负责身份和收入判断。其他章节链接到这些解释，不重复铺开同一组平台表。
- 合规章按“下一里程碑前处理／满足条件才涉及／扩大业务时复查”组织决定。每项要写触发条件、动作、可交付结果与证据；必要的个案询问给出完整材料示例，不能用“咨询专业人士”结束所有问题。
- 定价章应交付一份完整报价及取舍；获客章应交付适合具体渠道的发布材料和复盘样例；基础设施章应展示部署与恢复的实际验收产物。任何未实际执行的部分明确标为示例，不填造结果。

## 图文方向

- 使用imagegen创作与具体场景有关的原创编辑插画，统一为克制的纸感、墨线与暖色点缀，呼应站点现有米白、深灰和陶土橙。配图先说明要帮助读者理解什么，再生成；不采用通用“地球＋火箭＋美元”图案。
- 主题图表现从开发、交付到核对回款的工作过程；精确资金流、订阅状态与数据流用可编辑图示，重要文字和数字保留在正文中。真实界面操作以脱敏截图佐证，AI插画不能冒充账户或收款凭证。
- 在相关段落放图，提供中文alt与有信息量的图注。检查390px手机宽度的主体与文字，资源落在本主题assets目录；提示词、模式、用途和局限保存在research中的资产记录。
- 先以快速入门和合规章形成完整图文样章并按新标准验收，再将写法推广到其余章节；当前全部章节仍是待精修的初稿，不能因增加插画而升级状态。

## 硬性要求

- 研究不能停在官方文档。围绕每章的关键决定，主动检索中文和英文的独立开发者复盘、实操教程、深度分析与社区讨论；产品验证、定价、获客、支付接入及运营尤其需要实践材料。按docs/content-guide.md §6判断来源能支持什么，不能将所有非官方文章一律降为线索。
- 对重要经验记录作者、时间、所在地区、主体身份、产品类型、规模、采取的行动与所报告结果；找失败、退款/封禁、迁移和相反意见，辨别推广利益与幸存者偏差。不同文章重复同一案例不能算独立佐证；不具备相同条件的海外公司经历不能直接套给大陆个人。
- 将材料归纳为自己的判断：哪些做法在什么条件下有效，代价是什么，反例为何不同，本书读者可以借鉴哪一步。保留有归属的故事和关键过程，不能仅把外链加到文末，也不能把他人的经历改写成自己的实测。
- 涉及费率、准入条件、政策、额度的每一句都必须有引用，现行规则以对应平台或监管来源核对；亲历文章支持其作者在特定条件下报告的经历，独立分析支持有证据的比较与解释，不自动证明当前规则或人人适用。
- 不确定某平台是否接受中国大陆个人时，必须写明“截至某日期，官方文档的表述是……”，不能凭印象下结论。
- 外汇与税务内容统一引用国家外汇管理局、国家税务总局等官方来源，并附免责声明（已在 `topic.yaml` 中配置）。
- 不推荐任何违规绕过方式（例如借用他人身份开户、虚构经营信息）。读者问到时，说明风险并给出合规路径。
