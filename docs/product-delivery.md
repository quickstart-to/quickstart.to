# 产品交付清单与验收标准

基线：已批准的 [方案设计 v2](design.md)，及维护者于 2026-10-12 再次明确的“按原方案交付，不按轻量版缩减范围”。本清单用于追踪交付，不替代方案、不将未完成能力改成可选项。状态基于 `ddb2b9a`；本分支开发与验证结果另记在各项证据中，未合并、未部署不记为线上完成。

## 状态和完成门槛

- **已交付**：有已合并实现及对应环境验收证据。
- **部分交付**：已有实现，但缺能力或实际环境证据。
- **待交付**：缺实现；“配置了定时器”“有技能文件”不等于实际运行。
- **后续阶段**：原方案 P4 的既定顺序，仍在完整清单中。

每项分别记录实现 PR、自动检查、浏览器验收、staging／生产版本及未解决问题。合成记录、维护者操作和独立读者结果分开。不用完成百分比代替明确缺口。P2 完成需本表全部 P2 必需项通过；单个工程 PR 可以交付一组完整能力，但不得宣称整个 P2 已完成。

## 实施顺序与本次正式划线／讨论交付

1. 本清单先落库；工程分支持续更新，不修改主题正文或核验日期。
2. 实现 H01–H06、D01–D02 的完整读写与阅读体验，同时补齐这些新增路径需要的 M01–M02、F01、S01–S02、O05。保留旧反馈接口和 ID；优先增量表及兼容读取，不为重命名丢弃既有数据。
3. 完成 A01–A03、V01–V02、F02–F03 的剩余项；平台配置不足时如实保留缺口，先完成可审查实现，再由维护者完成必须本人办理的供应商配置。
4. 完成 P3 维护运营及真实读者回访。第二主题与导出按原 P4 顺序推进。

顺序可以根据技术依赖调整，完整范围不能自动减少。本次完成划线／讨论不等于 P2 全部完成；邮箱、Google、匿名投票及主动维护仍需各自实际验收。
